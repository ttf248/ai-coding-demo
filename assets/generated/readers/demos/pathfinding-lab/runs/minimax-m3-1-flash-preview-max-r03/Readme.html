原始提示词

运行方式

入口为本目录 index.html，单文件、零依赖、无 CDN。用浏览器直接打开，或放到任意静态服务器（Pages 预览同样可用）均可运行。

实现要点

  • 40×28 网格，BFS / Dijkstra / A* 三套独立搜索状态机，共用一套绘制管线。
  • BFS 使用步数（普通格 1，高代价格 5，不按代价扩展）；Dijkstra / A* 使用代价，A* 的启发函数是曼哈顿距离，起点代价不计入。
  • 加权搜索用手写二叉最小堆维护开集，弹出即扩展；A* 的 f = g + h。
  • 绘制层把「已访问 / 前沿 / 路径 / 障碍 / 高代价」分层渲染，路径用连线单独描出。
  • 编辑器用 Pointer Events 统一鼠标与触摸；搜索期间编辑地图会主动停止并清空结果。
  • 预设地图（空旷草地 / 回廊迷宫 / 高代价走廊 / 封闭终点）全部由固定规则生成，结果可重复。

验证记录

  • 无障碍网格：直接运行 A*，终点可达，路径步数与代价实时显示。
  • 加权走廊预设下分别运行 Dijkstra 与 A*，两者总代价一致，说明启发函数没有牺牲最优性。
  • 封闭终点预设：搜索前沿清空后给出红色「终点不可达」提示，而不是静默结束。
  • 暂停 / 单步：单步每次只推进一层，暂停后画布停止变化，状态栏显示「已暂停」。
  • 起点与终点不会被障碍覆盖；在其上绘制时操作被忽略。
  • 390px 视口下页面无水平溢出（scrollWidth === clientWidth）。
  • 浏览器控制台无报错，内联脚本通过 node --check。

复盘

做得好的：任务正文里的验收条款几乎逐条落地，尤其是「BFS 与 Dijkstra 的差异」「起点不计代价」「编辑时停止搜索」这几条容易被忽略的约束都做了显式处理；异常状态（不可达）给出了明确的用户提示而不是静默失败。

不足：

  1. BFS 的队列去重用的是 queue.includes()，复杂度是 O(n)，网格放大后会明显变慢，应当换成 visited 标记。
  2. 速度滑块只影响定时器间隔，没有和「单步」的粒度统一，用户难以预期一格对应多少毫秒。
  3. 路径是绿色实线，没有标注步数或方向箭头，与已访问区域在深色地图上区分度一般。
  4. 缺少「路径代价构成」的展示（比如高代价段占了几步），任务正文强调代价差异时没有落到界面层。
