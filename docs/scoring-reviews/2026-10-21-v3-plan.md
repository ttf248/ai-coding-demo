# 2026-10-21 全量截图与评分复核方案

这是 v3 的实施方案；在全量图像审阅完成并切换校验器之前，站点当前评分仍使用 v2。不得把本方案或自动采集完成误报为已经完成视觉评分。

## 现有方案的缺口

- 四个任务项各混合多个要求，难以解释“有控件但没有结果”“完成一个流程但缺少其他页面”等不同缺口。
- 视觉维度只有一个整数及一段总评，对齐、密度、文字、图例、资源完整性等没有分别记录，重复扣分和主观漂移不易追查。
- 单张截图及不同取景、等待时间、视口、输入状态，会让拍摄者选择影响分数。初始空画布不能直接归因于模型实现失败。
- 原型页面可能在折叠区域或其他登记入口，首屏不能代表全部交付；图片粒子需要上传输入，相机与手部追踪不能靠说明文字证明。
- 单图指纹没有绑定完整采集过程、其他页面、手机取景和运行错误。旧总分相近也不表示两条证据具有同样可信程度。
- 任务可见成果与运行正确性仍是两种证据。重拍后的截图和自动点击日志不能证明数值算法、全部交互、真实手势、后端或性能已验收。

## v3 的判断单位

机器定义草案在 `catalog/scoring-rubric-v3.json`：每份任务正文拆为八个任务项，每项 0–5 分，共 40 分。构图拆四项、可读性三项、操作表达两项、精修三项，每项 0–5 分，视觉合计仍为 60 分。全量重新观察这二十项，禁止从旧总分按比例换算。

每维先写具体观察与限制，再按锚点评分；同一问题指定主要扣分项。分数不因厂商、档位、费用、任务复杂度而变化。设计授权、原始输入缺失和当前模块范围仍单独记录，不用统一模板补造要求。

证据置信度独立记录，不当加分或乘数。主体未展示为 `insufficient`，无入口的历史记录为 `unavailable`；新图环境受阻不以旧图冒充本轮成果。旧 PNG 和旧评分保留供追查。

本轮登记共 371 条，359 条有预览入口，12 条无入口。包括已归档主题的历史证据检查；不重新调用模型，不修改源码或依赖，不启动需要独立部署的后端。

`node scripts/capture-screenshots.mjs --batch 2026-10-21` 使用本地只读静态服务器、Chromium、DPR 1，记录桌面 1440×900 和手机 390×844。适用时通过真实控件进行种子输入、串联预设、寻路运行、鼠标注入或图片上传，并记录结果态。原型补拍全文或底部，以及所有已登记的其他入口。无真实相机或手部时不模拟视频和关键点。

所有新 PNG 放在对应 run 的 `captures/2026-10-21/`，旧图不覆盖。采集清单放在 `catalog/screenshot-captures/2026-10-21/`，包含操作、环境、页面、失败资源、异常和各图指纹；已有完整清单可继续采集，未完成的非空目录必须人工检查后用新批次重拍。默认运行不写 run.json、不自动打分。

盲审时隐藏模型、档位、费用和旧分，逐条查看全部新图，再核对原始输入差异。高分、低分和疑似取景问题放大原图校准；需要补拍的条目使用新批次和真实操作，保留失败尝试。12 条无入口逐条登记原因，不制造阅读页或占位图来伪装产物。

完成审阅后绑定新截图，保存原始评分、完整新评分及规则快照，并执行生成、验证、单元测试、浏览器检查再提交。`tests/scoring-v3.test.mjs` 检查二十项定义、缺图边界和完整证据绑定；正式切换时接入 validate，仍须逐图审阅。
