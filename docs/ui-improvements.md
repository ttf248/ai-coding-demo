# 页面交互优化方案

## 目标与实施

沿用浅灰、白色和蓝色配色，让浏览作品、选择实验、比较实现的路径更直接。页面继续读取生成目录，实验身份、输入与模型排序来自既有元数据。

| 页面 | 调整 | 验收方式 |
| --- | --- | --- |
| 首页 | 明确全部档案与当前范围；手机默认显示搜索和筛选按钮；已应用条件保持可见 | 筛选、清除、刷新恢复及 390px 布局 |
| 首页卡片 | 缩短截图区域；标题后直接展示操作；截图标明当前模型；版本选择保持明显 | 首屏入口、列表视图、筛选后的截图和预览来源一致 |
| 图片 | 首两张优先加载；其他懒加载；加载、失败和重试反馈 | 模拟请求失败后重试成功，图片与预览来源不变 |
| 主题 | 默认紧凑完整清单；手机排为双列记录卡片，日期、供应商、工具、费用、耗时及操作直接可见 | 首屏可见第一条操作，无横向溢出；筛选、排序和实验锚点可用 |
| 费用 | 显示批次总额与案例数摘要，展开查看原始口径与备注 | 不把批次总额视作单次实验费用 |
| 耗时 | 独立展示已记录时长，明确批次或单次口径；保留不精确描述及未知值 | 不拆算批次耗时，不从订阅额度或文件时间推断 |
| 对比 | 完整模型身份独占一行；输入关系始终可见；重载、卸载、记录放入更多 | 两侧独立操作、未操作侧状态保留、四宫格和分享恢复 |
| 手机对比 | 显示单屏轮看说明及模型标签，隐藏桌面布局选择器 | 只加载当前侧，切换重新加载，分享保留已有布局参数 |

## 设计约定

主要文字使用 14–15px，辅助说明尽量使用 12–13px；手机新增操作区域采用至少 44px 的点击高度。原始截图文件不被修改或替换，展示层默认使用 contain 保留完整内容；竖版整页长截图在封面与缩略图位置允许使用由原始截图派生的顶部裁剪缩略图，完整截图始终可通过放大预览与「查看原图」查看，派生缩略图只新增文件、不写回原始截图。折叠操作使用原生 details 或带 aria-expanded 的按钮；卡片操作在 DOM 中位于标题之后，键盘浏览顺序与视觉一致。

## 检查

执行 generate、validate、单元测试、浏览器回归、JavaScript 语法检查和 diff 空白检查。浏览器回归覆盖根路径与 Pages 子路径，并增加手机卡片、图片失败重试、首屏入口和单侧预览的验证。
